# شاشة المطبخ المستضافة

نُشرت الخدمة وفُعّلت على staging: https://d3ozj1vp60o5bp.cloudfront.net

تفاصيل النشر وحدود التحقق موثقة في `docs/hosted-kitchen-rollout-561.json`. نجح فحص HTTPS ورمز الربط ورفض الوصول غير المعتمد. يبقى اعتماد المالك واختبار الطلبات الفعلية ومتصفح Samsung.

يفتح المالك رابط HTTPS على التلفزيون، ثم يضيف الرمز من «الوصولات والطباعة ← شاشات المطبخ» في تطبيق المطعم. الرمز صالح لخمس دقائق؛ الربط يتطلب جلسة مالك فعّالة، دون اشتراط إعادة تسجيل الدخول خلال آخر خمس دقائق. لكل شاشة نمط عرض أو مطبخ تفاعلي واعتماد مستقل ينتهي بعد ثلاثين يومًا، ويمكن للمالك إلغاؤه.

الشاشة لا تحفظ جلسة المالك، ولا تعرض بيانات الاتصال أو الأسعار. تعرض الأصناف وخياراتها وملاحظات التحضير فقط. التحديث عبر أحداث الطلبات؛ لا توجد قراءة دورية للطلبات. فحص بقاء اعتماد الاتصال كل دقيقة مستقل عن جلب الطلبات. العودة من انقطاع الاتصال تجلب لقطة كاملة. الأزرار معطلة أثناء الانقطاع، ولا ترسل الشاشة تغييرات مؤجلة بعده.

إجراءات التحضير والجاهزية تستخدم كاتب الطلبات الحالي وضوابط الإلغاء والمراجعة والفرع، وتضيف شرط مراجعة الطلب وهوية الشاشة لسجل التدقيق. لا تقبل الشاشة الطلب ولا تلغيه ولا تؤكد تسليمه للسائق.

## تجهيز الحزمة

من جذر المستودع:

```sh
node backend/kitchen-display/build.cjs
npm ci --prefix backend/kitchen-display/.build --omit=dev --ignore-scripts
sam validate --lint --template-file backend/kitchen-display/template.yaml
```

الحزمة المعزولة تحفظ هيكل المسارات. الخدمتان القائمتان تستخدمان هيكلًا مختلفًا؛ `inspect-staging.py` يحمّل نسخهما للقراءة والنسخ الاحتياطي، و`prepare-existing.py` يضيف التغييرات الصغيرة فوقهما دون المساس ببقية ملفاتهما. لا ينشر أي منهما.

بعد تفعيل مستهلك الأحداث، تُشغّل تهيئة الفهرس مرة واحدة بواسطة `backfill.cjs` (المعاينة افتراضية؛ الكتابة تتطلب `--apply` و`STAGE=staging`). لا يقرأ العرض فهرسًا لم تكتمل تهيئته. مستهلك الأحداث يحدّث مفاتيح الطلبات فقط ثم يرسل إشعار تغيير؛ كل عرض يعيد التحقق من الطلب الأصلي. فشل مستهلك الأحداث يعاد لمحرك Streams لإعادة المحاولة.

ملفات الويب في `kitchen-web`. يولَّد `config.js` من مخرجات الاستضافة: `api` و`actions` و`websocket`؛ لا تضاف أسرار إليه. يجب رفعه مع `Cache-Control: no-store` وبقية الملفات بمدة قصيرة، وعدم رفع ملفات الاختبار.

## التحقق المتبقي

اختبارات محلية تغطي الصلاحيات، الحالات، قفل الأزرار، بيانات الشاشة، الريموت والاتصال. يبقى بعد النشر اختبار جهازين فعليين، حالات الإلغاء والتسليم، مراقبة تأخر Streams، قياس وصول التحديث، ومتصفح ريموت Samsung. لا تُعد محاكاة Chrome إثباتًا لهذه الحالات الفعلية.
